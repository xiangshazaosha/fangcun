# 从成品提炼新风格：可复验方法

适用：用户确认一份成品，要求抽取可复用主题/动效/素材。不是把当前文案换成另一标题，更不是把截图作为模板。[代码 C34]

## 1. 冻结证据，而不是凭记忆选版本

识别实际浏览器入口、生成器、最终接受的修订和交互行为。记录源文件 SHA-256、页数、素材数量、截图及已拒绝的方案。成品在 `成品/<演示名称>/` 单独冻结；重复发布使用新版本目录，不能覆盖已归档交付。[代码 C36]

## 2. 把内容分成四类

| 类别 | 提炼策略 |
|---|---|
| 主题身份 | 色彩、字体、材质、构图、节奏与禁用项 → 风格文档/主题变量 |
| 通用机制 | 舞台、推进、命中、状态机、帧动画、图层 → 可执行模块及统一代码引用 |
| 可选素材 | 场景、船模、人物、背景视频 → 单独依赖清单与开关，不变成默认品牌 |
| 题目专有内容 | 单位、Logo、业务文案、专业公式、文件名 → 只留成品，不进通用新稿默认值 |

可以保留用户授权默认 Logo；不能将“此素材在这份成品里可用”推断为任何用途都可商用。

## 3. 查完整依赖闭包

不仅扫描 HTML 的 src/href；同时检查 CSS url、JS import/fetch、动态拼接精灵图、iframe 内部资源、纹理、字体、生成器的本地文件依赖以及许可证。动态数量必须明确，比如 15 张精灵图不能只打包当时屏幕载入的 3 张。[代码 C34、C36]

优先复用已验证源代码，只改宿主接口、路径、参数和身份，不重写成“看起来差不多”的动画。机械抽取用源 hash 与唯一边界校验；源版本变化就停止并复核，避免静默提错代码。不要用全项目字符串替换清品牌。

## 4. 保存四份互相可定位的产物

- `references/styles/<id>.md`：设计规律、适用边界、背景/模型选择、布局与交互合同、代码引用。
- `assets/styles/<id>/`：独立生成器、示例内容、主题、模块、素材和许可证。代码仅此一份可编辑真源，统一登记到 code-reference，不在多个文档反复粘贴。
- `references/extractions/<id>-vN.md/json`：来源、hash、逐文件映射、必要变换、验证命令/结果、局限。
- `references/styles/registry.json`：新增唯一 id/version/reference/runtime/codeRefs/defaultBackground/defaultModel。已存在条目不删除、不换名、不合并文件夹。

## 5. 参数化与开箱入口

把文字、标题、品牌、素材模式作为数据/参数，把舞台/行为作为代码。给出至少封面、章节、内容、收束的真实样页；有粒子则验证换词。有生成器时，它和模板/模块是源，不让用户只能手改产物。[代码 C35]

新主题默认无动态背景/无额外模型，用户显式选择时再载入。全中文主题须检查字形覆盖；旧成品的字体子集不等于新稿完整字库。

## 6. 以失败可见的测试验收

1. 在**全新目录**仅从风格包创建与原题目无关的新稿。
2. 从该目录独立 HTTP 服务播放；拦截所有其他 origin（包括原项目端口），暴露隐性依赖。仅在原项目 4174 下打开不算独立验证。
3. 实测开场→封面、逐项推进→翻页、水面与控件优先级、鼠标离开/重进、不同章节主体、减弱动效；失败则修复后重测。
4. 1920×1080、1280×720 和手机视口截图；检查全字库/品牌清洗、没有遮挡/裁切/重新排版。
5. 禁用可选素材再测一遍，确保默认不自动启用。
6. 对旧风格文档和既有代码段验 hash，证明新增而非覆盖。

静态校验或 hash 只能证明文件完整，不能证明动效/交互正确；必须与浏览器行为测试、截图检查一起使用。声称“开箱即用”须注明平台前提（本项目为 Python 3.10+ 和支持 WebGL 的现代浏览器）。

## 7. 新增以后其他风格

复用以上方法，新建 id 文件夹与记录，追加 code-reference 编号、registry 项和 style-catalog 路由。`new_deck.py` 根据注册表定位 runtime，不把新主题写死进旧风格代码。设计不同的风格实现自己的 `deck.json + build_deck.py` 接口，满足启动协议即可；若只有参考文档，用 `documented`，不要冒称已有可运行模板。[代码 C34–C36]
